# Implementation status — Milestone 5 (2026-11-17)

**Release decision: NOT APPROVED for live financial records.** Backend tests are evidence of limited correctness, not a substitute for browser, financial, security and regulatory acceptance.

## Architecture and verified backend

- One company is the only security/accounting boundary. Every user has one immutable company; there is no organization layer, login slug or company switcher.
- One fresh `migrations/0001_initial.sql`; no compatibility or legacy import scheme.
- The TypeScript backend, SQLite accounting engine, company RBAC, contacts, invoices, partial settlements, AI tools and complete database/attachment backups are implemented.
- Milestone 5 adds a guarded one-click **basic** chart for an empty book, with posting defaults. It is not a statutory Iranian chart and must be checked by a professional before real use.
- Milestone 5 also adds interrupted AI turn recovery and expiring stale approvals. Recovery never replays a financial operation.
- Existing and new backend integration tests have been executed on **Linux / Node 22.16**. Exact results are recorded in the final handoff report.

## Browser code and test infrastructure

- Source: bilingual Persian RTL/English LTR shell, contacts, multi-line sales/purchase invoices, receipts/payments, partial settlements, ledger, inventory, administration, AI conversation workspace and contextual drawer.
- Milestone 5 adds an invoice print/PDF-friendly layout and spreadsheet-safe trial balance CSV export.
- A disposable Playwright/Chromium E2E fixture now covers sign-in/company scope, posting an invoice, ledger navigation, RTL/mobile navigation and the assistant drawer.
- **Not executed here:** installing React/Playwright dependencies, actual frontend typecheck/Vite build, Playwright E2E, accessibility or visual review. This environment cannot resolve the npm registry. `web/pnpm-lock.yaml` is consequently absent and must be generated by a real install and committed. No fabricated package lockfile is included.

## AI scope

- Implemented: configurable compatible provider, encrypted API key, contextual company tools, user-owned persistent conversations, bounded read tool calls, one authorized compound financial command per turn, preview/approval, immutable financial posting through application services, recovery of abandoned provider turns and expired approvals.
- Not implemented: unconstrained autonomous planning, external bank transfers, live-provider certification, configurable retention/deletion, or a guarantee that a particular third-party model understands Rial/Toman correctly without confirmation.
- The application still works with AI disabled.

## Explicit exclusions and release blockers

- Source financial workflows currently operate in the accounting base currency. Realized/unrealized FX settlements and full revaluation remain unfinished.
- Inventory tracks quantities only: no financially valued stock/COGS. Do not treat it as an inventory ERP.
- Tax schedules exist, but complete automatic tax journal posting and Iranian statutory submission do not.
- Complete refunds, bank reconciliation, fiscal-year close, advanced imports and several statement/report variants remain incomplete.
- Node 24 primary target, Node 22.16+ and 26 compatibility, and Windows/macOS builds require real verification. The current root `@types/node`/lock pairing is not aligned to Node 24 and needs a reviewed connected-machine dependency update.
- Production security review, TLS proxy/LAN checks, backup scheduling/off-host restore drill, live model acceptance, accessibility, real-user accounting acceptance, and Iranian compliance review remain blockers.
